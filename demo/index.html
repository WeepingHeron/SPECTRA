04 · CONVENTIONAL APPROACHES VS SPECTRA

기존 DB와 엑셀 취합은
왜 근거 체인을 보증하지 못하는가.

환경 모델 출력 → BOM spreadsheet → 시험 PDF → 수기 조건 대조 → 검토·보완으로 이어지는 동안, 사람이 끊어진 근거를 다시 연결해야 한다.

현재 취합 workflow · 서로 다른 파일과 승인 단계
  • 정확한 부품 식별: 제조사·공정·다이·로트가 시험 원문과 같은지 다시 대조
  • 시험 조건: 조사 조건과 event coverage가 이번 임무 판단에 맞는지 다시 확인
  • 임무 적용성: 환경·차폐·수명 변경이 기존 가정을 깨는지 다시 추적
  • 권리·승인 trace: 원문 접근 권리와 검토·보완 이력을 별도로 연결
SPECTRA가 지원하는 방식 · Multi-Agent Evidence Assurance
  • 기계 검증형 데이터 규칙: JSON Schema와 RFC 8785 정규화 해시로 환경·성적서·완화 정책을 결속
  • 부품 식별 정합성(Exact Identity): 제조사·공정·다이·로트 및 시험 조건이 일치하지 않는 성적서는 거절
  • 변경 파급 감사: 암호학적 해시 체인으로 궤도나 차폐 변경 시 깨진 가정을 감지
  • Fail-Closed: 방사선 시험 증거가 결측되거나 불충분하면 HOLD로 격리
NASA REAG NASA 고다드 방사선 효과 DBESA ESCIES 유럽우주국 부품 정보교환 포털Fail-Closed 근거 결측 시 HOLD로 닫는 원칙

05 · COTS ADOPTION & RADIATION UNCERTAINTY

왜 COTS인가, 그리고 왜 검증인가.
조달 가능성과 임무별 검증 사이의 간극.

COTS는 상용 조달 선택지를 넓히지만, 조달 가능성이 곧 우주 임무 적합성을 뜻하지 않는다. exact identity와 시험 근거를 임무 조건에 맞춰 다시 검증해야 한다.

07 · SCOPE & RELIABILITY

SPECTRA가 지원하는 범위와,
지원하지 않는 범위를 함께 보여준다.

지원하는 범위
  • 방사선 근거 체인 & 감사: 궤도 환경·부품 시험 성적서·완화 가정을 추적 가능한 증거 패킷으로 결합
  • Fail-Closed 판단: 근거가 0건이거나 모델 지원 범위 밖이면 HOLD로 판단 보류
  • 결정론적 Multi-Agent 실행: 환경·부품·판정 역할이 데이터 무결성을 독립 대조
지원하지 않는 범위
  • 임무 적합성 자동 인증 도구가 아님: AI가 부품 적합성을 임의로 보증하거나 단독 승인하지 않음
  • 생성형 AI 추측에 의존하지 않음: 물리 규칙과 불변 데이터 검증 경로를 사용
  • 가속기 빔 시험의 대체가 아님: 시험 성적서 없이 숫자를 지어내지 않음
